## 1. 제품 정의

### 1.1 정체성 결정

세 가지 방향을 검토한 뒤 **A. 순수 집중 시간 타이머**로 확정했다.

| 방향 | 핵심 가치 | AI의 역할 | 결과 |
|---|---|---|---|
| **A. 순수 집중 시간 타이머** | 온전히 집중한 시간만 센다 | 보조: 자리 이탈 감지로 시간 보정 | ✅ 채택 |
| B. AI 집중도 코치 | AI가 집중 상태를 알려준다 | 주인공 | 데이터·정확도 문제로 기각 |
| C. 기록·성장 시각화 | 잔디·통계 중심 | 거의 없음 | 동기 장치가 약해 기각 |

채택 이유
- 유지할 강점(온디바이스, Overtime, 순수 집중 시간, '오롯'이라는 이름)이 모두 A를 가리킨다.
- AI 판단 기준을 "졸음/집중"에서 "자리에 있는가, 화면을 보고 있는가"로 낮추면 학습 데이터 없이도 작동하고 오탐이 크게 줄어든다.

### 1.2 핵심 메시지

> 사용자가 집중할 시간을 정하고, 그 시간 동안 학습이든 업무든 과제든 **한 가지에 온전히 집중**한다.

### 1.3 이름과 부제

- 이름: **오롯 (Orot)** — '온전히, 모자람 없이'라는 뜻이 '순수 집중 시간'과 직접 연결된다.
- App Store 제약: 앱 이름과 부제는 각각 최대 30자. 이름과 부제 모두 검색 대상이므로 같은 단어를 반복하지 않는다.

**추천안 (최종 확정 필요)**

| 구분 | 한국어 | 영문 |
|---|---|---|
| 앱 이름 | 오롯: 뽀모도로 집중 타이머 | Orot: Pomodoro Focus Timer |
| 부제 | 공부도 업무도, 정한 시간만큼 오롯이 | Set a time. Focus fully. |

대안
- 별 메타포 유지형 부제: 집중한 만큼 별이 뜨는 공부·업무 타이머
- 영문 부제 대안: Fully focus on study or work / Pure focus time, on-device

별 메타포는 부제 대신 **첫 스크린샷 문구**가 맡는다.
> 예) "집중할수록 도시의 불이 꺼지고 별이 떠요"

## 2. 배경: 확인된 문제

| 영역 | 문제 |
|---|---|
| 정체성 | 잔디 타이머(사용자 가치) → AI 집중도(포트폴리오) → 서버 확장(학습)으로 동기가 다른 층이 쌓여 핵심 가치가 흐려짐 |
| 컨셉 | Forest(나무 성장/상실 회피), Focus Flight(비행 여정) 같은 메타포가 없음. GitHub 잔디는 기록 시각화일 뿐 동기 장치가 약함 |
| AI | 학습 데이터 부족, EAR 임계값 방식의 개인차·각도·안경 문제, "졸음 ≠ 비집중" 한계로 정확도 낮음 |

## 3. 유지할 강점

- **100% 온디바이스 처리**: 영상·얼굴 데이터를 기기 밖으로 보내지 않음
- **Overtime 모드**: 흐름이 끊기지 않는 타이머
- **순수 집중 시간 측정**
- **가로 거치 탁상시계 UI**
- **발열 대응**: 1fps 스로틀링, Thermal 모니터링
- 이름 '오롯(온전히)'과 '순수 집중 시간'의 의미적 연결

## 4. 원칙

1. 만들 수 있는 것보다 **만들 이유가 검증된 것**부터 만든다.
2. 서버 확장(Orot Hub)은 출시와 사용 지표 확보 이후로 보류한다.
3. AI 오탐이 사용자에게 **처벌로 느껴지지 않게** 한다 (획득 프레임).
4. 결정이 필요한 지점은 선택지와 트레이드오프를 함께 기록한다.

## 5. 컨셉: 도시의 밤하늘에서 별을 되찾다

### 5.1 핵심 문장

> **도시의 불빛(소음·방해) 때문에 별(온전한 집중)이 안 보인다 → 방해를 걷어낸 시간만큼 별이 드러난다.**

사용자가 겪는 현실의 결핍(도시에서는 별을 볼 수 없다)과 앱의 측정 방식(방해를 뺀 순수 집중 시간)이 같은 구조를 가진다.

### 5.2 상실 프레임이 아닌 획득 프레임

Forest는 앱을 나가면 나무가 죽는 상실 회피를 쓴다. Orot은 AI가 이탈을 **자동으로** 판단하므로, 오탐이 생기면 사용자 잘못 없이 벌을 받게 된다.

- 이탈은 처벌이 아니라 **'멈춤'**: 별이 어두워지지 않고, 밝아지기만 멈춘다.
- 온전히 집중한 시간만 쌓이고, 빠진 시간은 그냥 쌓이지 않는다.
- 빨간 경고색이나 실패 연출을 쓰지 않는다.

### 5.3 이야기 구조

| 층 | 의미 | 앱에서 |
|---|---|---|
| 빛공해 도시 하늘 | 바쁜 일상, 방해, 흩어진 주의 | 시작 화면은 밝고 뿌연 도심의 밤하늘 |
| 별 | 온전히 집중한 시간 | 세션 하나가 별 하나, 순수 집중 비율이 높을수록 밝음 |
| 별자리 | 쌓인 노력이 만든 의미 | 28수를 채워 나감 |
| 달 | 실제 하늘과의 연결 | 오늘의 실제 달 위상 → "오늘 밤 진짜 하늘도 올려다보세요" |

### 5.4 기능 ↔ 메타포 매핑

| 기능 | 별 컨셉에서의 표현 |
|---|---|
| 순수 집중 시간 | 별의 **밝기(등급)**. 실제 천문학처럼 등급 숫자가 낮을수록 밝음 |
| 이탈 감지(멈춤) | 별빛이 잠시 모이기를 멈춤 |
| Overtime | 유성이 지나가거나 별이 한 단계 더 밝아짐 |
| 세션 진행 | 스카이라인의 창문 불빛이 하나씩 꺼지고 하늘이 어두워짐 |
| 기록(잔디 대체) | 날마다 만든 별들이 작은 밤하늘 조각으로 쌓임 |
| 온디바이스 | "당신의 하늘은 이 기기 안에만 있습니다" |

### 5.5 확장 아이디어 (v1.x 이후)

- **보틀 스케일(Bortle Scale) 성장**: 빛공해 정도를 1(가장 어두운 하늘)~9(도심 한복판)로 나눈 실제 관측 척도. 누적 집중 시간이 쌓일수록 9등급 도심 하늘에서 점점 어두운 하늘로 바뀌는 장기 성장 축.
- **낮/밤 하늘**: 낮에 한 세션은 "보이지 않지만 이미 거기 있는 별"로 저장하고 밤에 드러냄 → 저녁 회고 습관과 재방문 장치.

## 6. 별자리 시스템

### 6.1 진행 순서 (확정)

1. **한국 전통 별자리 28수** 완성 (천상열차분야지도 기반)
2. 이후 업데이트로 **해외 별자리** 세트 추가
3. 새 세트가 나오기 전에 모두 완성한 사용자에게 **나만의 별자리 만들기** 개방
   - 하트 등 원하는 모양, 별 밝기까지 직접 조절
   - 새 콘텐츠를 기다리는 동안의 이탈을 막는 엔드게임 장치

### 6.2 별 생성 규칙

- 세션 하나 = 별 하나
- 세션 시작 시 진행 중인 수의 **다음 빈자리**가 이번 세션의 목표가 됨
- 별의 밝기 = 순수 집중 비율 (예: 95% 이상 1등성, 60% 내외 4등성 — 정확한 구간은 구현 시 확정)
- 28수는 4방위(동·서·남·북) × 7수 구조

### 6.3 데이터

- 28수 별 위치·연결선 데이터 출처 확보 필요 (공개 성표·천문 소프트웨어 데이터는 **라이선스 확인 필수**)

## 8. 경쟁 분석과 차별점

### 8.1 경쟁 앱

| 앱 | 메타포 | Orot과의 관계 |
|---|---|---|
| Stellar – Study Timer | 세션마다 별·행성·성운 생성, 별자리 형성, 60종 이상 도감 수집 | 가장 가까운 경쟁자 |
| Star Focus | 실제 성표(HYG)의 별 사이를 오가는 성간 비행 | 실제 별 데이터, '여행' 메타포 |
| Orbis | 집중 시간이 행성이 되고 매달 은하가 자람 | 국내 개발자 앱, 국내 시장 직접 경쟁 |
| SolarFocus | 태양계·궤도 테마 타이머 | 우주 테마, 수집 요소 약함 |

공통점: 모두 "폰을 내려놓으면 = 집중"으로 판단하고, 우주는 판타지 공간이며 현실 하늘과의 연결이 없다.

### 8.2 Orot의 차별점

1. **빛공해 서사**: 도시 불빛이 꺼질수록 별이 드러나는 메커니즘
2. **현실 하늘과의 연결**: 실제 달 위상
3. **28수**: 한국 전통 별자리라는 문화적 정체성 (글로벌에서는 이국적 매력)
4. **카메라 기반 순수 집중 측정**: '앱을 떠났는가'가 아니라 '실제로 자리에 있었는가'

### 8.3 포지셔닝 원칙

- "우주를 만드는 앱"이 아니라 **"도시에서 잃어버린 진짜 밤하늘을 되찾는 앱"**
- 메시지와 디자인에서 **우주·은하·행성·성운** 어휘와 이미지를 피한다.

## 9. 판단 엔진: AI 단계화

### 9.1 결정

**컨셉을 먼저 잡고, ML 졸음 판단은 v2에서 추가한다.** 단, v1부터 판단 엔진을 교체할 수 있는 구조로 설계한다.

| | ML을 v1에 포함 | ✅ 규칙 기반 출시 → ML은 v2 |
|---|---|---|
| 출시 시점 | 데이터 수집·학습·검증 후 → 예측 불가 | 컨셉·디자인만 완성되면 가능 |
| 정확도 | 오탐이 "시간을 빼앗는" 경험이 됨 | Vision 기본 기능은 오탐이 적음 |
| 원칙 부합 | 졸음 판단의 사용자 근거가 아직 없음 | 실사용 피드백이 근거가 됨 |
| 포트폴리오 | ML이 드러나지만 완성도 논란 | "규칙 기반 출시 → 데이터 기반 고도화" 서사 |
| 모노레포 | ML 폴더가 iOS 출시를 막는 의존성 | ML은 독립 트랙으로 진행 |

### 9.2 과거 vs 현재 접근

| | 과거 (기존 Orot) | 현재 권장 |
|---|---|---|
| 판단 대상 | 졸음/집중 | 얼굴 존재 여부, 머리 방향(yaw/pitch) |
| 눈 감김 | 2D 랜드마크 → EAR 임계값 | (v2) 지속 시간 휴리스틱 + 개인 캘리브레이션, TrueDepth 기기는 ARKit `blendShapes[.eyeBlinkLeft]` 검토 (발열·배터리 부담 고려) |
| 판단 단위 | 프레임 단위 | 시간 창 단위 + 히스테리시스 |
| 모델 | 처음부터 직접 학습 | 규칙으로 출시 → 동의 기반 데이터로 학습 |

### 9.3 구조: Strategy + Decorator

타이머와 UI는 "지금 집중 상태인가"만 안다. 판단 방식은 프로토콜 뒤에 숨긴다.

```swift
// 컨셉이 의존하는 유일한 신호
enum FocusSignal: Equatable {
    case focusing
    case paused(reason: PauseReason)
}

enum PauseReason: Equatable {
    case faceAbsent      // v1: 자리 비움
    case lookingAway     // v1: 고개 돌림
    case drowsy          // v2: ML 졸음 판단
}

protocol FocusDetector {
    /// 1fps로 스로틀링된 프레임 입력
    func evaluate(_ observation: FaceObservation) -> FocusSignal
}

// v1: 학습 데이터 없이 Vision만 사용
struct RuleBasedDetector: FocusDetector {
    var maxYaw: Double = 0.5    // rad, 캘리브레이션으로 개인화
    func evaluate(_ o: FaceObservation) -> FocusSignal {
        guard o.isFaceDetected else { return .paused(reason: .faceAbsent) }
        if abs(o.yaw) > maxYaw { return .paused(reason: .lookingAway) }
        return .focusing
    }
}

// v2: 규칙 결과에 ML 판단을 덧붙임
struct MLAugmentedDetector: FocusDetector {
    let base: FocusDetector
    let model: DrowsinessModel   // CoreML 래퍼
    func evaluate(_ o: FaceObservation) -> FocusSignal {
        let signal = base.evaluate(o)
        guard signal == .focusing else { return signal }
        return model.isDrowsy(o) ? .paused(reason: .drowsy) : .focusing
    }
}
```

### 9.4 처리 흐름

1. 카메라(1fps) → Vision(`VNDetectFaceRectanglesRequest`, `VNDetectFaceLandmarksRequest`) → `FaceObservation`
2. `FocusDetector.evaluate` → `FocusSignal`
3. 시간 창 + 히스테리시스로 안정화 (예: 5초 이상 지속될 때만 상태 전환)
4. 타이머는 `.focusing`일 때만 순수 집중 시간을 누적, UI는 이 상태만 반영
5. v2에서는 DI 시점에 `RuleBasedDetector`를 `MLAugmentedDetector`로 감싸기만 함 (설정의 실험 기능 토글)

### 9.5 ML 트랙 (모노레포 `ML/`)

- iOS는 `FocusDetector` 프로토콜까지만 의존 → `.mlmodel` 없이도 빌드·출시 가능
- 지금은 "오프라인 실험장": 기존 MobileNetV3 멀티태스크 파이프라인 정리, 평가 지표(오탐률 기준선) 정의
- 출시 후 데이터 확보: 영상이 아닌 **랜드마크 수치 특징 + 사용자 자기보고 라벨**("방금 졸았어요")만, **명시적 동의(opt-in)** 기반으로 수집 → 개인정보 처리방침과 심사 문구에 반영 필요
- 공개 졸음 데이터셋(UTA-RLDD, NTHU-DDD 등)은 상당수가 연구 목적 한정 → 상용 학습 전에 라이선스 확인 필수

## 10. 스탠바이와 잠금화면

### 10.1 핵심 제약

iOS 17 스탠바이(충전 중 가로 거치 잠금 상태)에 Orot을 표시할 수 있지만, **잠금·백그라운드 상태에서는 카메라를 쓸 수 없다.** 따라서 스탠바이 동안에는 자리 이탈 감지가 동작하지 않는다.

### 10.2 정책 (추천안, 확정 필요)

| 선택지 | 동작 | 트레이드오프 |
|---|---|---|
| **A. 앱 화면 = 측정, 스탠바이 = 보기 전용** | 측정은 앱을 켜둔 탁상시계 화면에서, 잠그면 진행 상황만 표시 | 핵심 가치 유지, "앱을 켜둬야 정확" 안내 필요 |
| B. 잠그면 자동 일시정지 | 타이머가 멈춤 | 정직하지만 불편 |
| **C. 잠금 구간은 '미확인 시간'으로 기록** | 타이머는 계속, 그 구간은 별 밝기 계산에서 제외 | Overtime 철학과 맞음, 로직 복잡 |

**추천: A를 기본으로 C를 함께 적용.** 앱 화면은 `isIdleTimerDisabled = true`로 꺼지지 않는 탁상시계, 잠그면 Live Activity로 진행 상황 표시, 잠금 구간은 "미확인 시간"으로 정직하게 기록.

### 10.3 과거 vs 현재

| | iOS 16 이전 | iOS 17 이후 |
|---|---|---|
| 가로 탁상시계 | 앱을 켜두고 `isIdleTimerDisabled` | 앱 화면 + 스탠바이 |
| 잠금 상태 표시 | 알림만 가능 | Live Activity(진행 중 세션), 위젯(오늘의 별·달 위상) |
| 실시간 타이머 | 앱이 계속 화면 갱신 | `Text(timerInterval:)`로 시스템이 초 단위 갱신 |

### 10.4 Live Activity 뼈대

```swift
import ActivityKit
import WidgetKit
import SwiftUI

struct FocusSessionAttributes: ActivityAttributes {
    struct ContentState: Codable, Hashable {
        var endDate: Date          // 종료 예정 시각
        var isMeasured: Bool       // false = 잠금 상태라 감지가 안 되는 구간
        var litWindows: Int        // 남은 창문 불빛 수 (메타포 진행도)
    }
    var focusLabel: String         // "학습", "업무", "과제"
}

struct FocusLiveActivity: Widget {
    var body: some WidgetConfiguration {
        ActivityConfiguration(for: FocusSessionAttributes.self) { context in
            // 잠금화면 / 스탠바이 전체 화면
            HStack {
                VStack(alignment: .leading) {
                    Text(context.attributes.focusLabel)
                        .font(.caption)
                    Text(timerInterval: Date.now...context.state.endDate,
                         countsDown: true)
                        .font(.system(size: 56, weight: .thin, design: .rounded))
                        .monospacedDigit()
                }
                Spacer()
                SkylineView(litWindows: context.state.litWindows)
            }
            .padding()
        } dynamicIsland: { context in
            DynamicIsland {
                DynamicIslandExpandedRegion(.center) {
                    Text(timerInterval: Date.now...context.state.endDate,
                         countsDown: true)
                }
            } compactLeading: {
                Image(systemName: "moon.stars")
            } compactTrailing: {
                Text(timerInterval: Date.now...context.state.endDate,
                     countsDown: true).monospacedDigit()
            } minimal: {
                Image(systemName: "star.fill")
            }
        }
    }
}
```

### 10.5 처리 흐름

1. 세션 시작 → 카메라 감지 시작 + `Activity.request()`로 Live Activity 시작
2. 화면 잠금 → `scenePhase == .background` → 카메라 정지, `isMeasured = false`, 미확인 구간 시작 시각 기록
3. 충전 중 + 가로 → 스탠바이가 Live Activity를 전체 화면 표시
4. 앱 복귀 → 카메라 재개, `isMeasured = true`, 미확인 구간을 기록에 반영
5. 세션 종료 → `activity.end()`, 별 생성 (미확인 구간은 밝기 계산에서 제외)

### 10.6 주의 사항

- **야간 모드**: 스탠바이는 어두운 곳에서 화면 전체를 빨간 단색으로 바꾼다 → 색이 아니라 **밝기와 형태**로 정보를 구분
- **애니메이션**: Live Activity는 연속 애니메이션이 제한된다 → 상태가 바뀔 때의 정적 화면으로 설계
- **지속 시간 한도**: Live Activity는 시스템이 일정 시간 뒤 종료한다 → 장시간 Overtime 대응 필요 (구현 시 Apple 문서로 수치 확인)
- **위젯**: 세션이 없을 때 스탠바이 위젯으로 오늘의 별 개수, 실제 달 위상, 28수 진행도 표시

## 11. 화면 설계

### 11.1 이동 구조 (추천안, 확정 필요)

|---|---|---|
| **A. 하단 탭 3개: 집중 / 밤하늘 / 기록** + 설정은 우측 상단 | 핵심 가치 3개가 한눈에, 밤하늘을 자주 보게 됨 | 세션·휴식 중 탭바 숨김 필요 |
| B. 단일 홈 + 하위 화면 | 타이머 앱다운 단순함 | 별자리 수집이 묻혀 동기 장치 약화 |

### 11.2 v1 화면 목록

### 11.3 세션 화면 상태

| 상태 | 표현 |
|---|---|
| 집중 중 | 창문 불빛이 꺼지고, 이번 세션의 별이 빈자리에서 천천히 밝아짐 |
| 잠시 멈춤 | 별이 어두워지지 않고 밝아지기만 멈춤. "별빛이 잠시 모이기를 멈췄어요" 톤 |
| 오버타임 | 정한 시간이 지나도 흐름 유지, 유성 연출 |
| 세션 완료 | 시간 UI가 흐려지고 점선이 새 별까지 이어짐, 진행도 갱신 (예: 심(心) 3/5 → 4/5) |
| 발열 모드 | 감지 간격을 늘렸다는 조용한 배너 |

### 11.4 가로 세션: 3레이어 구조

화면을 영역으로 나누지 않고 **깊이(레이어)**로 나눈다.

| 레이어 | 내용 | 시각적 비중 |
|---|---|---|
| 앞 | 남은 시간, 집중 대상, 순수 집중 비율 | 가장 밝고 큼 (탁상시계 역할 우선) |
| 중간 | 하단 도시 스카이라인, 창문 불빛 | 하단 1/3, 어둡고 단순하게 |
| 뒤 | 하늘 = 진행 중인 28수 하나 + 실제 달 | 낮은 대비 |

- 배치: 시간은 왼쪽, 별자리는 하늘 오른쪽 위
- 별자리 표현: 채워진 별 = 밝은 점, 연결선 = 점선, 빈 자리 = 희미한 고리
- 진행도는 작은 텍스트 (예: "심(心) · 3 / 5")
- 28수 전체는 '나의 밤하늘' 화면이 담당, 세션 화면에는 수 하나만
- 설정의 **별자리 표시 밝기(끔/은은하게/선명하게)**로 시간만 보고 싶은 사용자 대응

```swift
struct SessionLandscapeView: View {
    @ObservedObject var vm: SessionViewModel

    var body: some View {
        ZStack {
            // 뒤: 하늘 + 진행 중인 수 + 달
            SkyCanvasView(
                mansion: vm.currentMansion,
                filledCount: vm.filledStars,
                birthingBrightness: vm.liveBrightness   // 0.0 ~ 1.0
            )
            // 중간: 스카이라인 (불빛 = 남은 시간 비율)
            SkylineView(litRatio: vm.remainingRatio)
                .frame(maxHeight: .infinity, alignment: .bottom)
            // 앞: 시계
            ClockOverlayView(remaining: vm.remaining,
                             label: vm.focusLabel,
                             purity: vm.purity)
                .frame(maxWidth: .infinity, alignment: .leading)
        }
        .ignoresSafeArea()
    }
}
```

- 뒤 레이어는 `Canvas` + `TimelineView(.periodic(from:by: 1))`로 1초 단위만 다시 그려 1fps 스로틀링·발열 방침과 맞춘다.

### 11.5 세로 세션

- 위 약 50%: 하늘 + 28수 + 달 (가로보다 별자리를 크게)
- 가운데: 남은 시간 (가장 큰 요소 유지)
- 아래: 스카이라인
- 기술적 장점: 세로 거치에서는 전면 카메라가 화면 위 중앙에 와서 얼굴이 정면으로 잡힘 → **세로를 기본 거치 방향으로 안내하는 것** 검토

### 11.6 설정 항목

| 섹션 | 항목 |
|---|---|
| 집중 | 기본 집중 시간, 휴식 시간, 긴 휴식 주기, 집중 대상 관리 |
| 감지 | 자리 이탈 감지 켜기/끄기, 민감도(3단계), 얼굴 위치 다시 맞추기 |
| 화면 | 별자리 표시 밝기, 화면 꺼짐 방지 |
| 알림 | 세션 종료 알림, 휴식 종료 알림, 사운드, 햅틱 |
| 데이터 | iCloud 동기화, 기록 내보내기, 모든 기록 삭제 |
| 개인정보 | 카메라 데이터 처리 방식 설명, 개인정보 처리방침 |
| 정보 | 버전, 문의하기, 오픈소스 라이선스 |

## 12. 디자인 원칙

- 다크 기반이지만 장시간 봐도 눈이 피로하지 않은 **저대비 톤**
- 화면을 오래 켜두므로 움직임은 **아주 느리고 은은하게**
- 멀리서도 **시간이 가장 먼저** 읽혀야 함
- 별자리는 항상 시간보다 대비가 낮게
- 금지: 은하·행성·성운·네온 사이버 등 "우주 앱" 느낌, 귀여운 캐릭터, 과한 그라데이션, 게임 같은 UI, 처벌을 연상시키는 빨간 경고색
- 문구: 처벌이 아닌 안내, "무슨 일이 생겼는지 + 무엇을 하면 되는지" 한 문장씩
- 스탠바이: 색이 아닌 밝기·형태로 정보 구분

### 13.4 그룹 2 — 집중 탭

```

   - 집중 대상 칩: 학습 / 업무 / 과제 / 직접 추가
   - 오늘 요약 한 줄: 오늘 만든 별 개수, 순수 집중 시간
   - 하늘 배경에 "이번 세션이 채울 별자리 자리"를 은은하게 미리 보여주기
   - 시작 버튼 1개만 강조
   - 우측 상단 설정 아이콘
2. 빈 상태 (첫 세션 전)
   - 별이 하나도 없는 밝은 도시 하늘
   - "첫 별을 띄워 보세요" 같은 초대형 문구 + 시작 버튼
3. 시작 직전 확인 (카메라 감지 켜짐 상태)
   - "얼굴이 잘 보이게 거치해 주세요" 짧은 안내와 카메라 상태 표시
   - 감지 없이 시작하기 선택지
```

### 13.5 그룹 3 — 밤하늘 탭

```
같은 디자인 시스템과 이동 구조로, 그룹 3 — 밤하늘 탭 화면을 만들어 주세요. 세로 모드입니다.

1. 나의 밤하늘 (28수 전체 성도)
   - 28수를 동·서·남·북 4방위(각 7수)로 묶어 보여주기
   - 완성한 수는 밝게, 진행 중인 수는 강조, 아직 시작 안 한 수는 희미한 윤곽
   - 상단: 전체 진행도(예: 5 / 28), 오늘의 실제 달 위상
   - 핀치 줌과 드래그로 탐색하는 하늘 지도 형태
2. 별자리 상세
   - 수의 한자·한글 이름, 짧은 의미 설명, 소속 방위
   - 별 하나하나를 누르면: 만들어진 날짜, 집중 대상, 순수 집중 비율(밝기 등급)
3. 별자리 완성 축하
   - 별자리 선이 모두 이어지는 순간, 이름과 짧은 이야기
   - 과하지 않게, 차분하고 감동적인 톤. 공유 버튼은 보조로
4. 28수 전체 완성 후 (엔드게임 예고)
   - "나만의 별자리 만들기"가 열린다는 안내 화면
```

### 13.6 그룹 4 — 기록 탭

```
같은 디자인 시스템과 이동 구조로, 그룹 4 — 기록 탭 화면을 만들어 주세요. 세로 모드입니다.

1. 기록 메인
   - 일 / 주 / 월 전환
   - 핵심 지표: 순수 집중 시간, 전체 세션 시간, 만든 별 개수
   - 일별 기록 시각화: 날마다 그날 만든 별들이 작은 밤하늘 조각으로 쌓이는 형태
     (기존 잔디 그리드를 대체하는 표현)
   - 집중 대상별 비율 (학습/업무/과제)
2. 세션 상세
   - 타임라인: 집중 중 / 잠시 멈춤 / 잠금 상태라 측정되지 않은 "미확인 구간"을 구분해 표시
   - 미확인 구간은 경고가 아니라 정보 톤 (예: "화면이 잠겨 있던 시간이에요")
   - 이 세션으로 만들어진 별과 밝기 등급
3. 빈 상태 (기록 없음)
```

### 13.7 그룹 5 — 설정

```
같은 디자인 시스템으로, 그룹 5 — 설정 화면을 만들어 주세요. 세로 모드, iOS 기본 설정 화면처럼 그룹 리스트 구조이되 앱 톤에 맞게.

[섹션 구성]
- 집중: 기본 집중 시간, 휴식 시간, 긴 휴식 주기, 집중 대상 관리
- 감지: 자리 이탈 감지 켜기/끄기, 민감도(3단계), 얼굴 위치 다시 맞추기
- 화면: 별자리 표시 밝기(끔/은은하게/선명하게), 화면 꺼짐 방지
- 알림: 세션 종료 알림, 휴식 종료 알림, 사운드, 햅틱
- 데이터: iCloud 동기화, 기록 내보내기, 모든 기록 삭제
- 개인정보: 카메라 데이터 처리 방식, 개인정보 처리방침
- 정보: 버전, 문의하기, 오픈소스 라이선스

[함께 요청]
1. 집중 대상 관리 하위 화면 (추가/이름 변경/삭제/순서 변경)
2. 카메라 데이터 처리 방식 설명 화면
   - "영상은 저장하거나 전송하지 않고, 기기 안에서 얼굴이 있는지만 확인합니다"를 그림과 함께 쉽게
3. 모든 기록 삭제 확인 대화상자 (되돌릴 수 없음을 명확히, 별자리 진행도도 함께 사라진다는 안내)
```

### 13.8 그룹 6 — 예외 상태

```
같은 디자인 시스템으로, 그룹 6 — 예외 상태 화면을 만들어 주세요. 해당되는 것은 세로/가로 둘 다.

1. 카메라를 사용할 수 없음 (다른 앱이 사용 중이거나 기기 제한)
   - 세션은 타이머만으로 계속할 수 있다는 선택지
2. 발열 모드 안내 (세션 중 배너 형태)
   - 기기가 뜨거워져 감지 간격을 늘렸다는 짧은 안내, 세션은 방해하지 않게
3. 카메라 권한이 나중에 꺼진 경우 (설정 앱으로 이동 버튼)
4. 알림 권한 거부 시 안내 (세션 종료를 놓칠 수 있다는 정도로 가볍게)
5. iCloud 동기화 실패 (조용한 배너, 기록은 기기에 안전하다는 안내)

[톤 원칙]
- 모든 예외 상태에 빨간 경고색 금지. 처벌이 아니라 안내.
- 문장은 "무슨 일이 생겼는지 + 무엇을 하면 되는지" 한 문장씩.
```

### 13.9 마무리 점검

```
지금까지 만든 전체 화면을 점검해 주세요.
- 디자인 시스템 토큰(컬러, 타이포, 간격)에서 벗어난 화면이 있는지
- 같은 역할의 컴포넌트(버튼, 칩, 배지)가 화면마다 다르게 생긴 곳이 있는지
- 다크 배경에서 대비가 부족한 텍스트가 있는지
- 문구 톤(처벌 없는 안내, 짧은 문장)이 어긋난 곳이 있는지
발견한 문제를 목록으로 정리하고 수정해 주세요.
```

### 13.10 요청 팁

- 현재 앱 스크린샷을 첨부하고 "유지할 것 / 버릴 것"을 표시하면 기존 강점을 살린 리디자인이 나온다.
- 수정 요청은 한 번에 하나씩, 구체적으로 (예: "스카이라인 높이를 화면 1/3로, 시간 숫자를 더 가늘게").
- 상태(state)를 항상 명시해서 SwiftUI View 상태와 1:1로 대응시킨다.
